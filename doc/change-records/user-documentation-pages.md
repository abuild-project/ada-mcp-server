# User documentation on GitHub Pages

Readers can start with one English guide to choose Mac/Codex Desktop, Managed
Cloud/Codex or direct Docker, run a source-bound Ada query and find the update,
rollback and support instructions. The Pages builder renders the start page
and four maintained user guides from `doc/`, so the repository remains the
source for both formats. Relative links work at the project Pages subpath.
Direct Docker links to current-release acquisition, and rollback routes
distinguish a compatible runtime selection, a retained Docker pair and an
entry replacement. Links to repository materials lead to GitHub. The site
includes the project's original MIT license text.

The maintained guides now identify the published RC6 pilot and record the
supplied consumer observations. Mac offline validation used the retained
RC5 image. A separate RC6 acquisition and restarted Desktop session
provided Doctor, a direct handshake and source-bound results in a resumed
Arca chat. A fresh Managed Cloud task used an existing plugin setup and
retained RC6 runtime. These results cover the reported requests and setup.
See the [support matrix](../support.md#rc6-consumer-observations) for the
checks that remain open. Published RC6 assets and release notes retain their
original contents.

Development checks covered Markdown examples, links, dependency pins, Ruff,
strict typing and the rendered site at the project subpath. The host tests
cover relative and GitHub main guide links, immutable tag URLs and rejection
of broken links and fragments. The complete CI chain builds the same preview
and retains it as the `user-documentation-preview` artifact. Publication uses
a separate manual workflow on main after an authorized maintainer configures
Pages to use GitHub Actions. See the [dated plan](../plans/user-documentation-pages.md).
