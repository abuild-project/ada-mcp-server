# Ada MCP Server 0.2.0-rc.1

This is the first pilot prerelease prepared by the independently maintained
abuild-project continuation of
[MDBrothers/ada-mcp-server](https://github.com/MDBrothers/ada-mcp-server).
The selected personal fork's history, authorship and MIT notices are retained.
It is an independent distribution and maintenance line, not an upstream release.

The coordinated SemVer is `0.2.0-rc.1`; Python package and MCP initialization
metadata report its PEP 440 form `0.2.0rc1`. Server, container, host tooling and
lightweight skill use one version. This is a prerelease for pilot acceptance;
pin its immutable source/artifact metadata when evaluating it.

## Included workflow

- A standalone Linux/AMD64 Debian Trixie container with GNAT 14, pinned GPRbuild,
  Ada Language Server and hash-locked Python dependencies.
- Explicit GPR, dependency-search-path and scenario selection across Ada
  repositories, preserving the selected ancestor-GPR behavior.
- Source-anchored project, symbol, navigation and per-file diagnostic queries
  within the [documented support scope](https://github.com/abuild-project/ada-mcp-server/blob/v0.2.0-rc.1/doc/support.md).
- Hash-verified tooling/image acquisition, explicit host bindings and a
  read-only, nonroot, network-isolated runtime with private HOME and evidence.
- Source/image/version receipts binding release packaging to the exact tested
  source, Python distributions and immutable Docker target.

The source and own tooling use MIT; redistributed components keep their own
licenses and corresponding-source obligations. See
[licensing](https://github.com/abuild-project/ada-mcp-server/blob/v0.2.0-rc.1/doc/licensing.md).

## Acceptance and limits

The release source must pass the complete documented AMD64 Trixie chain,
including tests, coverage, Ruff, strict typing, packaging, documentation and
real ALS/MCP controls. Generated-artifact host acceptance exercises Linux
numeric identities `1000:1000` and `501:20` and confirmed EOF/container removal.
Only a successful CI run at the exact selected `main` commit supplies the
release artifacts; an earlier candidate's successful run does not certify it.

MCP file diagnostics do not replace compiler, test or coverage CI. The 19-tool
catalog does not promise support for every advertised operation. macOS/Apple
Silicon emulation, Docker Desktop/Colima sharing, native Claude/OpenCode
registration and other unaccepted tools remain in development. Linux numeric
identity tests do not establish actual Mac compatibility.

Public download verification, anonymous registry access and ordinary acquisition
in a fresh managed Cloud task need their own observed evidence. Publication
enables those consumer tests; this source document does not claim they have
already passed. The pilot can be published before the deferred Mac/native-client
acceptance, while preserving those limits.

## Artifact availability

[GitHub Releases](https://github.com/abuild-project/ada-mcp-server/releases)
is the authority for published versions and assets. Generated candidate URLs
are prepared targets until publication succeeds. GitHub Releases and GHCR are
the distribution channels; this release does not publish a PyPI package.
Follow [host setup](https://github.com/abuild-project/ada-mcp-server/blob/v0.2.0-rc.1/doc/setup.md)
using the exact published tooling/image hashes
and the recorded registry digest, rather than a mutable `latest` image tag.
