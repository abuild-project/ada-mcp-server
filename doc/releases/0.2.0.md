# Ada MCP Server 0.2.0

0.2.0 is the first stable standalone Ada MCP release. It runs the existing
Ada Language Server in Linux/AMD64 Debian Trixie Docker with GNAT 14,
locked MCP SDK 1.30.0 and workflow contract 1. Python package and MCP server
metadata report `0.2.0`. Stable names the release channel and retained supported
workflow. It does not promote every advertised tool or client to full support.

Versioned release and asset links are publication targets until the non-draft
stable release, authoritative hashes and anonymous registry access are verified.
Install only after those checks. Published RCs remain immutable rollback options.

## Changes and use

- The standalone image includes pinned XML/Ada development packages, making
  Schema, DOM, SAX, Input and Unicode GPR projects and Ada sources available.
  Canonical checks compile the aggregate-import fixture and navigate over real
  STDIO to the independently located installed DOM.Core declaration.
- New Codex native fragments expose 16 read tools plus rename previews under
  normal client policy. Only rename is annotated `readOnlyHint=true`.
  Request `preview=true`, inspect the proposals and expect `applied=false`.
  Application remains unsupported. Existing users must generate a new fragment,
  back up and explicitly merge only the Ada entry, then reconnect.
- The maintained user guides cover Mac/Codex, Managed Cloud and direct Docker,
  first queries, updates and rollback, with a GitHub Pages build.
- Host Python pinning, explicit update policy, bounded fail-open advisories,
  exact runtime selection and immutable acquisition carry forward from RC6.
  Compatible selection-aware entries may keep their version while selecting
  the verified stable runtime. This release does not update an account plugin.

The supported workflow remains exact GPR/scenario selection, symbol queries,
definition/hover navigation, per-file diagnostics and bounded rename previews.
Other advertised semantic tools retain their individual development limits.
Builds, formatting and applied edits are outside the supported consumer flow.
Three pinned-ALS positional signature cases remain explicitly unaccepted.
Other native clients, native Cloud registration and native-host ALS remain
in development. Run the Ada project's own compiler/tests/coverage separately.
Projects still need their normal dependencies prepared. A project-build-derived
image remains a later release recommendation.

Supplied macOS 26.5.1 arm64 reports on the accepted pre-stable implementation
cover prepared Abuild XML/Ada navigation and direct native rename proposals
in fresh and resumed Desktop chats, with unchanged source hashes and
`applied=false`. Those bounded supplied reports are separate from independent
Mac replay and published stable-runtime consumer checks.
